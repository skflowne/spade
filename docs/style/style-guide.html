01

Overview

The design language is quiet by default, precise under interaction, and consistent across shared canvas surfaces.

i
Foundation, not a feature specification

This guide defines visual tokens, common controls, the canvas, and generic entity-node presentation. It does not introduce product capabilities or entity-specific interfaces.

01 / PRIORITY

Work first

Chrome creates hierarchy and orientation, then gets out of the way.

02 / TONE

Quiet by default

Neutral surfaces dominate. Color appears only when it communicates meaning.

03 / DENSITY

Dense, not cramped

Compact metadata coexists with readable type and reliable interaction targets.

04 / BEHAVIOR

Explicit boundaries

Node chrome owns dragging. Node bodies preserve selection and interaction.

07

Interaction & access

Fast, stable feedback with visible focus and no dependence on color alone.

Do

  • Use 120ms feedback and 180ms surface transitions.
  • Keep a visible 2px keyboard focus ring.
  • Pair semantic color with a label or icon.
  • Preserve text selection inside node bodies.
  • Respect reduced-motion preferences.

Don't

  • Animate the canvas after direct manipulation stops.
  • Use continuous glow, pulse, or scanning effects.
  • Translate or scale nodes on hover.
  • Use decorative gray for essential text.
  • Let hover be the only way to discover essential actions.
08

Implementation contract

Central tokens and native interaction states keep shared primitives consistent.

background: var(--cr-ink-850);
color: var(--cr-ink-100);
border: var(--cr-border);
border-radius: var(--cr-radius-panel);
transition: border-color var(--cr-duration-fast) var(--cr-ease-standard);
01
Centralize values

Consume semantic aliases rather than scattering hex values.

02
Keep primitives neutral

Base components must not encode entity type or application capability.

03
Use native states

Prefer :focus-visible, :disabled, and accessible state attributes.
