Testing

Automated-test policy and verification guidance.

Automated-test policy for SPADE. AGENTS.md owns the verification gate.

Layers

Layer Where Owns
Type contracts tests/domain.contract.ts Shared record exports and compile-time shapes, checked by npm run typecheck
Deterministic behavior Plain specs in tests/e2e, such as canvas-reducer, layout, workspace-gateway, agent-service, and control-server Shared and main-process logic without Electron: the reducer, tree, placement, validation, paths, the store and gateway in temporary directories, the Paseo adapter and agent service against fake drivers, the control server and CLI against tests/control-fakes.ts, and renderer models
Electron end-to-end Specs in tests/e2e that launch the built app, with ui-harness.ts and agent-harness.ts Startup, the host bridge, rendering, and interaction in the real desktop shell. Native dialogs, shell calls, and agent IPC handlers are replaced from the test through the Electron application handle
Live checks npm run test:live (playwright.live.config.ts, tests/live) and the validateLive.ts scripts in src/main/paseo and src/main/agents The real app or services against a running Paseo daemon with real agents. Opt-in and outside npm test

Test at the lowest deterministic layer that can fail for the reason under test. Cross-process and real-UI behavior belongs in Electron end-to-end coverage; static TypeScript contracts belong in the contract fixture. npm test also runs the merged P3 prototype's specs.

Isolation

  • Electron specs never touch the real profile: each runs with its user data in a fresh temporary directory.
  • Electron specs never reach a real Paseo daemon: the app launches with SPADE_DISABLE_PASEO=1, and agent behavior is scripted through the harness.
  • Production code has no test-only switches or branches. Tests inject fakes through the same constructor options and service interfaces the composition uses, or replace Electron APIs from the test.
  • Live checks spend real agent runs and depend on a running daemon, so they are never part of the gate.

Live checks

npm run test:live builds the app and runs tests/live/first-usable-version.spec.ts through playwright.live.config.ts: one real Claude agent drives B1 to B5 through the real UI against the local Paseo daemon, in scratch directories, and is archived afterwards with the paseo CLI. Screenshots and the main-process log go to artifacts/live. On headless Linux, use xvfb-run -a npm run test:live. Options:

  • SPADE_LIVE_MODEL — the agent's model (default claude-haiku-4-5).
  • SPADE_LIVE_MODE — the agent's mode (default default, which asks for permissions; the run answers them with the Allow button).
  • SPADE_LIVE_KEEP=1 — keep the scratch data.

It has passed against Paseo 0.17.0. It relaunches SPADE but never restarts the daemon, so reconciliation after a daemon restart is covered by fake-driver tests only.

Behavioral changes

  1. Write or extend the test first.
  2. Confirm it fails against unchanged production code for the expected reason.
  3. Implement the complete behavior.
  4. Run focused tests, then the full gate in AGENTS.md.

User-visible bug fixes require regression coverage. A skipped test is not a pass.

Test integrity

  • Name tests after durable behavior, never issues, PRs, authors, or review rounds.
  • Extend the existing behavior area instead of creating a parallel regression file.
  • Derive expected values independently of the production decision under test.
  • Never weaken or remove an assertion merely to make a test pass.
