Testing

Automated-test policy and verification guidance.

Automated-test policy for SPADE. AGENTS.md owns the verification gate.

Layers

Layer Where Owns
Type contracts tests/domain.contract.ts Shared record exports and compile-time shapes
Deterministic behavior Non-Electron specs in tests/e2e Domain and renderer behavior without a process boundary
Electron end-to-end tests/e2e/startup.spec.ts Startup, rendering, and interaction in the real desktop shell

Test at the lowest deterministic layer that can fail for the reason under test. Cross-process and real-UI behavior belongs in Electron end-to-end coverage; static TypeScript contracts belong in the contract fixture.

Behavioral changes

  1. Write or extend the test first.
  2. Confirm it fails against unchanged production code for the expected reason.
  3. Implement the complete behavior.
  4. Run focused tests, then the full gate in AGENTS.md.

User-visible bug fixes require regression coverage. A skipped test is not a pass.

Test integrity

  • Name tests after durable behavior, never issues, PRs, authors, or review rounds.
  • Extend the existing behavior area instead of creating a parallel regression file.
  • Derive expected values independently of the production decision under test.
  • Never weaken or remove an assertion merely to make a test pass.
