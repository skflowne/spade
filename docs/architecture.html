Architecture

How the current application fits together and where planned integrations belong.

This page is a visual map. The foundation describes what is implemented today; the plan contains detailed product decisions and proposals.

Implemented Planned boundary

Current application

SPADE currently has one Electron window, one React renderer, and a small shared core. The renderer projects one deterministic mock record set into dedicated-project and global-project canvas strategies, with in-memory node and per-project viewport state. There are no external integrations or persistent storage.

Core data relationships

The model separates the work being done from the place where it is done and from the items visible on the canvas. These are TypeScript records today; they are not persisted yet.

Entity and integration boundary

Canvas behavior stays generic. A node type is registered through an entity definition, which currently provides its metadata and creation adapter. The plan extends this boundary with entity-specific renderers, actions, and production integrations.

Architecture rules

  • The generic canvas owns node position, size, selection, connections, and lifecycle.
  • An entity renderer owns only the content and actions specific to its node type.
  • Shared records are the common contract across application areas.
  • Connections describe provenance and context; they are not an execution graph.
  • External systems are accessed through dedicated adapters.
  • Planned boundaries remain proposals until a prototype proves them.
