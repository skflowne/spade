SPADE DOCUMENTATION

Foundation

What SPADE does today and the rules the current code relies on.

Current state

SPADE is an Electron desktop application that maps agent work as trees of nodes on a React Flow canvas. Bricks B1 to B5 of the plan are implemented; Group containers (B6) are not. The target platform is native Windows; development and the automated checks also run on Linux. This page describes only what exists now.

  • Projects. Open project… picks a folder with the native dialog and creates a project: that root directory plus one canvas. The sidebar lists projects, switches the visible canvas, restores each canvas's last viewport, and shows running agents and agents that need attention. Projects can be renamed, re-rooted, and removed; removal deletes only SPADE's records.
  • Trees. Every node can spawn children. Each spawn asks for a target: child of the source (default), a chosen node or tree, or a new tree. Nodes can be reparented with their whole branch, collapsed, branch-collapsed, archived and restored (alone or with their branch), and removed alone (children move up) or with their branch. references edges with an optional label link any two nodes without changing the tree.
  • Automatic placement. New nodes get a legible default size and a position chosen by one shared placement function. After a user spawn, the canvas centers the new node at a readable zoom; nodes created by agents never move the viewport.
  • Agents through Paseo. Paseo manages agents; SPADE is a view on top. An agent node the user creates starts a Paseo agent in the project root with a chosen provider, model, mode, and prompt. Its conversation renders Paseo's timeline; the user can prompt it with explicitly selected nodes as bounded context, interrupt it, answer permission requests, and change its mode. The agents Paseo reports as its children and its provider-native sub-agents are listed, collapsed, in the node's Agents pane, a drawer on the node's right edge that is closed by default. Each child row shows live status, provider, model, mode, errors, and pending permissions, which can be answered and changed there; Expand turns a child into a delegated child node, and Collapse into owner returns it to the list. Provider-native sub-agents open as nodes on demand. The sidebar's Paseo status has a refresh control.
  • Notes. Note nodes hold editable text. An unedited note follows changes made elsewhere, even while it is open; an edited note that meets a conflicting outside change offers Keep mine or Take theirs.
  • Viewers. Image nodes show PNG, JPEG, GIF, WebP, and SVG files by path, or images SPADE stored itself, sized to the image's aspect ratio and reloaded when the file changes. A network image outside the project shows "not loaded" until the user clicks Load. Web page nodes show http and https pages in an Electron guest <webview> with back, forward, reload, stop, and open-in-browser controls; at most 12 guests per canvas stay live. Below 50% zoom a page's guest is unmounted and a placeholder shows its title and URL; the page returns at the same URL above it. A crashed guest shows the failure, and Reload replaces it.
  • Rich conversation. Agent messages render Markdown, highlighted code, Mermaid diagrams, and live HTML answers (spade-html fences) with a window.spade submit and annotate bridge. File paths, folders, images, and URLs become actions: reveal or open in Explorer, copy, open in the default browser, or spawn as an Image or Web page node with the target choice.
  • Navigation and review. Search (Ctrl+K), focus history, a current-focus path, keyboard moves between related nodes, a minimap, Fit and Full height on every node, simplified node bodies below 50% zoom, an Activity panel of who changed what, and an Archived panel. Every focus move centers within the canvas area the breadcrumb bar and the minimap leave free; Fit all frames the nodes in the area the minimap leaves free.
  • Agent CLI. Agents read and change the canvas with the spade command, which talks to a local control server in the running app. Three launchers in the data directory run it: bin/spade (POSIX sh, also Git Bash on Windows), bin/spade.ps1 (PowerShell), and bin/spade.cmd (cmd.exe). Each agent is told how to call it in its initial prompt, with the launchers in that order on Windows, and fetches the spade-canvas skill with spade skill. Any one free-text argument can be - to read it from stdin, the safe way to pass arbitrary text. Without PASEO_AGENT_ID the CLI only reads; the user changes the canvas in SPADE itself.

There is no GitHub integration, worktree management, terminal, file editor, or Group container.

Core concepts

The shared records in src/shared/domain.ts carry data-format version 3:

RecordMeaning
ProjectA root directory, stored exactly as the user selected it, plus one canvas. Identity is the SPADE ID, never the path.
CanvasEverything on one project's canvas: nodes, edges, workspaces, the saved viewport, and the activity log.
CanvasNodeOne item on the canvas: entity type and version, title, position, optional size, collapsed, branch-collapsed and archived flags, workspace, validated config, and a resource reference or null. groupId is always null until groups exist.
CanvasEdgeA child edge (tree structure, with origin spawned, delegated, or artifact) or a references edge (context only).
WorkspaceThe directory an agent runs in, with Paseo's opaque workspace ID once known. Today there is one per project: its root.
ResourceRefThe exact identity of a resource owned elsewhere that a node points at: provider + kind + id. Only agent nodes carry one, for a Paseo agent or a provider-native sub-agent. Note, image, and web page nodes have null; an image's path or asset ID and a page's URL live only in the node's config.
ActorWho issued a command: the user, an agent (its Paseo agent ID, plus its own node while it is expanded and null while it is collapsed into its owner's list), or SPADE itself.
CanvasActivityOne attributed change: actor, command, summary, and affected nodes. A canvas keeps the newest 200.
AppSettingsThe last agent provider, model, and mode used (the saved default the UI offers, whose provider spade spawn agent also falls back to), conversation expansion defaults, and an optional Paseo daemon URL.

Node types are entity definitions in src/shared/builtinEntities.ts: note, agent, image, and webpage. Each declares its config validation, a default and a collapsed size, and what an agent is told about it.

Rules already enforced

Persistence and project safety

  • SPADE writes only inside <userData>/data: index.json (projects, selection, settings), canvases/<projectId>.json, backups/, assets/, and the agent-CLI files control.json and bin/. It never creates, changes, or deletes anything in a project directory. Removing a node or a project removes only SPADE records.
  • One main-process owner, the workspace gateway, applies every change to the records, one at a time in arrival order. The renderer, the agent CLI, and agent reconciliation all go through it. An entity adapter that creates an external resource runs outside that queue, after the command has been checked against the current canvas, so a slow agent spawn blocks no other change and a command that fails that check creates no resource. When a creation command fails after its adapter created the resource, the gateway asks the adapter to release it: the agent service archives the Paseo agent it just spawned.
  • Writes are atomic: a temporary file is flushed and then renamed over the target. Records are validated before they are written, and a canvas whose child edges are not a forest is never persisted.
  • Every stored document carries a format version. An older version is copied to backups/ before it is migrated; the step to format 3 drops the canvas's former dismissedResources list. An unreadable file is moved to backups/ and SPADE continues from empty records, showing the problem. A file written by a newer SPADE is left untouched and is never overwritten.
  • Images SPADE must keep itself are stored in assets/ under a content hash, limited to PNG, JPEG, GIF, WebP, and SVG up to 50 MB.
  • Paths are handled by one pure shared module, src/shared/paths.ts: drive letters, UNC paths, \\?\ long paths, and case-insensitive comparison.

Tree and placement

  • Structure comes only from child edges. A node has at most one parent; a reparent that would create a cycle is rejected. Entity types never change tree behavior.
  • Removing a node promotes its children to its parent, or makes them roots. Ownership is the exception: removing an agent node also removes the delegated agent nodes below it, and theirs, which return to their owners' lists; any other node hanging off them moves to the nearest surviving ancestor. Removing a whole branch is a separate command. Only references edges can be disconnected.
  • Placement is one pure function in src/shared/layout.ts. It never overlaps a non-archived node, keeps 96 between nodes of one tree and 240 from other trees, reserves a collapsed node's expanded footprint, and never moves an existing node.

Process boundaries

  • The renderer runs sandboxed with context isolation and no Node integration. Its only host access is the typed window.spadeHost bridge from the preload. The main process validates every argument and answers only the app window's main frame; the window cannot navigate away or open windows.
  • Files are revealed, never launched: files use showItemInFolder, openPath is used only for directories, and the default browser opens only http and https URLs.
  • A network path (a UNC share, or a \\?\ or \\.\ device path that is not a drive) outside the project root is never stat-ed, opened, watched, or served because of text in a conversation or a node's config. It shows as unchecked until the user explicitly asks for that path (Check this path, Load, Reveal); that request approves it for the rest of the session. Paths inside the project root are always allowed. A mapped drive letter cannot be told apart from a local drive and is not covered.
  • Local images reach the renderer only through the read-only spade-image: protocol, which serves GET requests for absolute, normalized image paths and stored assets, and refuses network paths that are not approved.
  • Web page guests are forced into the persist:spade-web partition, sandboxed, without preload or Node access, and limited to http and https. Popups load in the same guest, downloads are refused, and only clipboard-write and fullscreen permissions are granted.
  • All Paseo access goes through src/main/paseo, the only code that imports @getpaseo/client. The renderer and the CLI never talk to Paseo.

Agents

Paseo manages agents; SPADE is a view on top. SPADE observes what Paseo reports (agents, their parent identity, provider sub-agents, status, mode, permissions) and offers the user Paseo's own operations. It never creates, governs, fills in defaults for, or messages agents on behalf of other agents.

  • Commands from the user, from agents, and from reconciliation pass the same runtime validation (src/shared/commandValidation.ts) and the same reducer. The CLI cannot attach a resource reference to a new node and cannot change the viewport or workspace records.
  • Every canvas command carries its actor. Agent changes are always recorded in the activity log; the user's moves and resizes are not.
  • The caller is the Paseo agent named by the PASEO_AGENT_ID its CLI call carries, resolved through Paseo, not through a canvas node: an agent acts as itself whether it has a node of its own or is collapsed into its owner's list. It is accepted when it, or an owner up Paseo's parent chain, is shown on a canvas, and refused with unknown-agent otherwise. The activity log and the recently-changed markers attribute changes by agent. A change without an agent identity is refused with identity-required; reads need none. Nothing falls back to the user, and the CLI has no way to act as the user.
  • A collapsed child's project and default spawn target come from its nearest expanded owner: a node it spawns without naming a target becomes a child of that owner's node and is attributed to the child. Expanding the child later does not move what it spawned.
  • Errors reach the CLI with their stable code, whether they come from the reducer, the agent service (agent-missing, paseo-unavailable, …), or the control server; anything else is internal.
  • An agent the user creates starts in its project's root directory, with a few lines of SPADE instructions appended to its prompt.
  • spade spawn agent is a pass-through to Paseo with the caller as parent. Paseo places the child in the caller's workspace and directory, and SPADE appends no instructions. The provider comes from --provider or the user's saved default provider, and the command is refused when there is neither; without --model, the saved default model applies only when the provider is the saved default one; SPADE never fills in a mode. It creates no canvas node, prints the new agent's Paseo ID, and refuses --parent, --tree, --new-tree, --description, and --project. Agents message each other with Paseo's own tools; SPADE has no agent-to-agent messaging.
  • The spade-canvas skill and the agent instructions tell agents to create canvas nodes only when the user asks. This is guidance; the control server does not enforce it.
  • Nodes are never removed because Paseo is unreachable or no longer has the agent: the node is shown as stale or missing and keeps its children. Removing or archiving an agent node never stops or archives the Paseo agent; SPADE archives one only to roll back a spawn whose command failed.
  • Reconciliation never creates or removes nodes. The agent service follows every agent shown on a canvas and, recursively, every agent Paseo reports under it, by Paseo's durable parent identity. A child edge between two agent nodes means only Paseo's parent and child: an agent the user creates from an agent node starts a new tree placed next to that node, not connected to it. Delegated nodes and user-made child edges between agents saved before format 3 are kept as they are.
  • Ownership is direct. An agent's node lists its direct Paseo children; a collapsed child's own children nest under its row, so a pending permission, an error, or a finished run the user has not seen surfaces on the nearest expanded owner, in its header badges, its Agents toggle, and the sidebar counts. An expanded child lists its own children on its node. Only the direct children of an expanded node can be expanded.
  • An agent's mode is shown on its node and on each child row, and changed on the running agent through Paseo (setAgentMode). Modes are opaque provider IDs labelled from Paseo's provider discovery. Which mode a child gets is Paseo's rule, not SPADE's. Provider-native sub-agents have no mode.
  • The daemon URL comes from the setting, then SPADE_PASEO_URL, then the local daemon's paseo.pid or config.json, then Paseo's default. The refresh control in the sidebar's Paseo status, and saving the URL in Settings, resolve it again, reconnect, and reconcile. SPADE_PASEO_URL is read from SPADE's launch environment, so a changed value needs a restart. Agent references carry no daemon identity: after switching to another daemon, that daemon's agents show and agent nodes from the previous one appear missing, as expected.
  • What agents see is bounded: a prompt carries at most 12 selected nodes, each with clipped text, and CLI reads are paged at no more than 200 items. Full transcripts, pages, and files are never included.
  • The control server listens only on 127.0.0.1 with a random port and requires a bearer token from control.json. It refuses browser-origin requests, other Host headers, request bodies with unknown fields, and bodies over 1 MB.

Canvas and renderer

  • An active node body captures input until Escape or a click elsewhere. Collapsing, hiding, archiving, or removing the active node returns input to the canvas. Escape that closes a dialog, popover, or menu does not deactivate the node behind it; Escape inside an HTML answer returns control to the canvas unless the answer handled it.
  • Undo after an archive restores exactly the nodes that archive archived. Closing the spawn dialog while its node is being created does not cancel the creation; the node appears without taking focus.
  • A node body that fails recovers when its record changes and offers Retry.
  • Canvas pushes are structurally shared in the renderer store, so nodes whose records did not change do not re-render.
  • Each agent node's conversation UI state (draft, shared-context picks, pending annotations, loaded history, scroll position) survives collapse and level-of-detail changes for the renderer's lifetime. Path chips are re-checked when the conversation changes and when clicked; a failed check shows as unknown, not missing. Each HTML answer has at most one submission in flight.
  • A web page guest takes calls once it is attached, before dom-ready. An address set from outside the page, such as an agent changing the node's URL, wins over the page that was loading. Page zoom follows the canvas zoom once it settles.

Known gaps. The agent identity is the PASEO_AGENT_ID the caller's environment provides; a forged one is not detected. Mapped network drives are not covered by the network-path rule. None of the Windows launchers has been run on Windows, and there is no packaged build to show whether it can run them (Electron's RunAsNode fuse, asar). Agent changes can be reviewed in the Activity panel and on recently changed nodes, but there is no undo for them. HTML answers are not stored as separate artifact revisions: the document lives in the agent's message in Paseo, and annotations stay in memory until the answer is submitted. Long-duration web page stability and downloads (refused) are untested. Reconciliation after restarting the Paseo daemon is covered by fake-driver tests only.

Code structure

AreaResponsibility
src/sharedProcess-neutral core: records, entity definitions, the command set and its validation, the canvas reducer, the tree index, placement, paths, artifact detection, the bounded agent context, and the bridge types.
src/mainElectron main process. index.ts and composition.ts wire the services behind the interfaces in contracts.ts.
src/main/persistenceThe application-data store and the asset store: atomic writes, migrations, backups.
src/main/gatewayThe workspace gateway: the serialized owner of projects, settings, and canvases.
src/main/ipcThe window.spadeHost handlers and their argument validation.
src/main/paseoThe Paseo adapter on @getpaseo/client 0.17.0, daemon URL discovery, and timeline normalization.
src/main/agentsThe agent service: user spawns and pass-through child spawns, following Paseo agents and their children, caller lookup, runtimes, timelines, prompts, permissions, modes, and connection refresh.
src/main/filesThe read-only file service: reveal, the image protocol, image sizing and watching, the web page guest policy.
src/main/controlThe local control server for the agent CLI, its discovery file, launcher shims, and the instructions added to agent prompts.
src/cliThe spade CLI, bundled to out/main/cli.js and run by the launcher shims with the app's own executable.
src/preloadThe sandboxed CommonJS preload that exposes window.spadeHost.
src/rendererThe React UI: store, shell (sidebar, settings, notices, empty state), canvas (React Flow canvas, node wrapper, toolbar, dialogs, navigation, panels), entities (one renderer per node type), and rich (Markdown, Mermaid, HTML answers, artifact chips).
resources/skills/spade-canvasThe skill that teaches agents the CLI, printed by spade skill.

Developer commands

  • npm install — install dependencies from the lockfile.
  • npm run dev — start the desktop app for development.
  • npm run build — build the main process, CLI, preload, and renderer into out/.
  • node out/main/cli.js help — list the agent CLI commands after a build.
  • npm run docs:compare — serve the documentation with side-by-side comparison against the base branch. Added and removed content blocks are highlighted in green and red. Use -- --base <ref> --page docs/<page>.html to override the defaults.
  • npm run typecheck — check TypeScript types.
  • npm run lint — check source and configuration files.
  • npm test — build the app and run its automated checks. On headless Linux, use xvfb-run -a npm test.
  • npm run test:live — build, then drive the real app through B1 to B5 against a running Paseo daemon. It starts a real agent and is not part of npm test; see testing.

Setting SPADE_DISABLE_PASEO=1 starts the app without connecting to Paseo; SPADE_PASEO_URL overrides the discovered daemon address; it is read once, at launch.
