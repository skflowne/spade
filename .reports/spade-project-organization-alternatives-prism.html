SPADE / PROJECT ORGANIZATION FIELD GUIDE

Projects need a geometry.

Sidebar canvases choose isolation. A global canvas chooses territory. Four other geometries are worth seeing before SPADE commits: scale, tiling, focus, and routes.

4+ active projectssame recordsno dashboardsno cosmetic variants
01 / Executive brief

Add three prototypes; keep one as a wild card.

Prototype Atlas, Mosaic, and Rooms beside the two Issue #10 baselines.

They test genuinely different organizing commitments: one nested world entered by scale, several independent worlds composed at once, and separate worlds connected by memorable adjacency. Keep the Fisheye Constellation as the higher-risk fourth condition if time permits.

This is a design recommendation, not evidence that any model is superior. The available research supports interaction principles; only SPADE prototype use can establish fit.

03 / Four alternatives

Different worlds, different questions.

01PROTOTYPE FIRST

Zoomable Project Atlas

The portfolio is a map. Each project is a stable portal into its own full-resolution canvas.

Borrowed from

Zoomable interfaces and cartography: preserve a landmark while changing representation with scale. Pad++ established zoom as an interface substrate; SpaceTree later argued for semantic rather than unreadably tiny geometric scaling.[10][12]

Why it fits / fails

  • Cross-project awareness without four full graphs.
  • Project location can remain stable.
  • Risk: thumbnails become a stealth dashboard.
  • Risk: scale transitions can disorient.

Decisive test

Can someone scan four projects, enter a specific issue, and return to the portfolio without losing their place?

Minimum: four anchored portals, saved atlas and project viewports, one bounded thumbnail grammar.

02PROTOTYPE SECOND

Project Mosaic

A persistent tiling workbench shows several independent project canvases at once—no shared coordinates, no global graph.

Borrowed from

Tiling window managers, control rooms, and split-screen workbenches: compose independent contexts rather than merge them. Research comparing tiled and overlapping windows found task- and user-dependent trade-offs—not a universal winner.[13]

Why it fits / fails

  • Best expression of simultaneous activity.
  • Each project keeps its own mental map.
  • Risk: tiny nodes and heavy rendering.
  • Risk: the desktop becomes another canvas to clean.

Decisive test

Does seeing two to four live local canvases improve cross-repository work enough to justify reduced canvas size?

Minimum: 2×2 and split layouts, compact semantic rendering, independent pan/zoom.

03WILD CARD

Fisheye Constellation

The active project expands to readable scale; neighboring projects remain compressed, stable context around it.

Borrowed from

Focus+context visualizations: detailed “neighborhoods” near the focus and compressed landmarks farther away. Furnas formalized fisheye views; SpaceTree showed the value of stable relative positions and readable-or-aggregated levels.[11][12]

Why it fits / fails

  • Awareness survives while one project dominates.
  • Switching can feel continuous, not modal.
  • Risk: motion and resizing erase spatial memory.
  • Risk: it collapses into styled global groups.

Decisive test

Can adaptive focus preserve orientation better than a hard canvas switch without making the scene unstable?

It only qualifies as new if inactive projects are semantic summaries, not tiny full groups on one global plane.

04TEST WITH RELATED REPOS

Project Rooms

Each project is a room; a persistent floor plan and deliberate doorways make adjacency the navigation structure.

Borrowed from

Architecture, indoor maps, and game hubs: bounded rooms, doors, corridors, and levels create memorable thresholds. Indoor-map standards explicitly distinguish these place types; Task Gallery explored task grouping in a navigable spatial environment.[8][14]

Why it fits / fails

  • Separation stays concrete; routes add continuity.
  • Strong for stable product families.
  • Risk: invented adjacency implies coupling.
  • Risk: corridors become decorative overhead.

Decisive test

Do users remember and use repository adjacency—or does the metaphor merely slow direct switching?

Run both related and unrelated four-project scenarios; the contrast is mandatory.

05 / Prototype order

Change one spatial law at a time.

Retain both baselines

Sidebar canvases and global project groups remain the controls. Use the existing realistic shared fixture.[1]

Add Atlas

Lowest domain-model risk. Tests overview-to-detail continuity and cross-project scanning.

Add Mosaic

Tests genuine simultaneous work. Keep project coordinate systems independent.

Gate Rooms + Fisheye

Rooms needs meaningful adjacency; Fisheye needs stable, low-motion transitions.

Common task script for all conditions
  1. Locate the project with a blocked review while two other projects have active agent work.
  2. Resume one issue, inspect its five workspaces, then move to a related issue in another project.
  3. Return to the exact first-project work-item view without using search.
  4. Explain which project, work item, and workspace the focused node belongs to.
  5. Describe what one visible edge means. Reject any condition that invites “this runs next” interpretations.

Observe route choice, hesitation, wrong-project landings, viewport recovery, and the participant’s explanation of the spatial model. Do not turn visual preference into a productivity conclusion.

06 / Boundary check

Interesting does not mean organizational.

Tabs, switchers, recents, search

Ways to access dedicated canvases. They do not change what the primary project space is.

Minimaps, dashboards, status decks

Awareness layers. Useful later, but they sit on top of an organization model.

Colors, planets, hull shapes

Visual skins for the global-territory baseline unless they alter containment and navigation semantics.

Metro lines and pipelines

They elevate sequence and hand-off, conflicting with SPADE edges as provenance rather than execution.[2]

Project × work-item matrix

A grid can give fixed addresses, but it shifts SPADE toward a board and compresses branching provenance into cells.

3D buildings

Depth is not required for the Rooms hypothesis. Test 2D adjacency and thresholds before accepting occlusion and navigation cost.

07 / Evidence & limits

Precedent suggests; prototypes decide.

Research combined SPADE’s canonical model, the live issue, implementation documentation, and primary HCI/platform precedents. Load-bearing claims were checked directly. Historical sources are used for durable interaction principles, not as proof that an old interface should be copied.

What is establishedSPADE’s records separate project, work item, workspace, node, and edge; React Flow can express subflows; virtual desktops establish an isolation/visibility boundary; HCI literature documents zoom, fisheye, tiling, and spatial-task metaphors.[3][6]
What remains unknownNo cited controlled study compares these models for spatial agent-development work. Their cognitive cost, density limits, and operational fit remain hypotheses.

Method and evidence limitations

The Explore research pass searched for organizational primitives rather than app feature inventories, then classified candidates by their authoritative top-level container: isolated surface, shared territory, nested scale, composed windows, adaptive focus, or routed rooms. Concepts that only add retrieval, status, or decoration were excluded.

Source dates span 1986–2026 because the report concerns enduring interaction structures. Citation does not imply direct transferability. In particular, no evidence here demonstrates that semantic zoom, fisheye views, tiling, or room metaphors improve SPADE task time or cognitive load.
